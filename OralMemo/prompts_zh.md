# OralMemBench 提示词中文版


# 第零步（Report 长程病例：时间线抽取与校验反馈）

## 0.1 时间线抽取（抽取模型）

从一篇长程病例报告的正文、时间线表格与图注中，抽出**严格忠于原文、按时间排序**的结构化时间线；可带上一轮校验模型的反馈进行自我修正。

```
你正在从一篇已发表的口腔/颌面/牙科长程病例报告，构建 OralMemBench-Longitudinal —— 一个按「时间轴」组织的多模态纵向记忆评测基准。

你的任务：阅读报告正文及其时间线表格，产出一份严格忠于事实、按时间顺序排列的结构化时间线。这必须能泛化到任意此类报告，因此请从文本中推断结构；不要假定固定的疾病或固定的就诊次数。

硬性规则：
1. 只使用下方 SOURCE 中「明确陈述」的事实。绝不臆造、平均、四舍五入或「修正」数值。
2. 每个数字、单位、百分比、牙位（FDI）、左右侧、日期、基因/变异、否定表述，都必须与原文完全一致。
3. 当叙述性文字与「表格」冲突时，以「表格」为准。
4. 不要做原文没有给出的算术（例如不要用减法推算牙数）。
5. 把每个不同的临床时间点各拆成一个 timepoint，按时间先后排列，全部保留（含很短的）。尤其要把「最早描述的临床事件」也作为第一个 timepoint——例如产前/孕期检出、出生、或首次转诊/首诊——即便它是以叙述性背景出现的；不要丢弃转诊时的鉴别诊断、家族史、相关阴性等信息。
6. 每个 timepoint 内，把发现拆成原子条目（每条只含一个临床事实）。
7. 只有当某图注（按日期/描述）明确对应某条发现时，才把该发现的 "figure_ref" 设为所提供的某个图标签；否则设为 null。
8. 只返回严格、合法的 JSON。不要 markdown、代码围栏、注释或多余逗号。

输出 JSON 结构（键名固定）：
{
  "timepoints": [
    {
      "label": "简短时间标签，如 2017-06 或某时期",
      "date_text": "原文中人类可读的日期/时期",
      "t_months": 距「最早时间点」的整数月数（把 0 锚定在最早的临床时间点——产前/出生/转诊/首诊；其余据所述年龄或日期估算）,
      "stage_type": "baseline_visit | treatment | followup_visit | outcome",
      "modality": ["TEXT_QA","DP","XR","CT","DERM","GENE", ...],
      "findings": [
        {"topic": "简短主题，如 periodontal status", "statement": "一句忠实于原文的事实陈述", "figure_ref": "Figure N 或 null"}
      ],
      "decision": "该时间点的关键临床决策（或 null）",
      "rationale": "决策的原文依据（或 null）"
    }
  ],
  "held_out": {
    "diagnosis": "统一诊断及其所述依据",
    "treatment": "实际实施的整体长期治疗策略概述",
    "prognosis": "整个随访期的长期结局"
  }
}

可用于 figure_ref 的图（标签 -> 图注，可能为空）：
$figures_block

$feedback_block

===== SOURCE：时间线表格（逐时间点数值以此为准） =====
$tables_text

===== SOURCE：全文 =====
$fulltext
```

## 0.2 时间线校验（校验模型 / critic）

对照原文、表格与**图注**，逐条核验抽取出的时间线；输出问题清单与修正建议，回灌给抽取模型形成反馈闭环。**图注也算原文的一部分**，并**禁止自行做算术**，以避免把原文确有的事实误判为「臆造」。

```
你是一名严格的医学事实核查员，服务于一个纵向口腔/牙科病例报告基准。
给你 (A) 原始报告正文、时间线表格，以及其「图注」，和 (B) 从中抽取的结构化时间线。请「仅」依据 (A) 校验 (B)，不得使用外部知识。

什么算作 SOURCE (A)：下方的全文、时间线表格，以及图注「全都」是原文的一部分。图注中陈述的事实即为「有支撑」（不要判为臆造）。

关键的防误报规则：
- 不要自己计算、求和或推算总数。若原文明确陈述了某个数字（如「共 47 次就诊」），就当它正确。只有当原文对同一量给出「不同」数值时，才判该数字有误。
- 在判定「未找到」之前，请检索 (A) 的全部内容：全文 + 表格 + 图注。
- 只标记「确实与原文矛盾」或「在 (A) 全部内容中都不存在」的内容。

核查项：
1. 事实支撑：每条 "statement"、"decision"、"rationale" 及每个 held_out 字段都必须在 (A) 中有支撑。只标记真正无支撑/臆造/被篡改的内容。
2. 数值保真：数字、单位、%、牙位（FDI）、日期、基因/变异必须与 (A) 完全一致（同一量叙述与表格冲突时以表格为准）。
3. 跨时间点的内部逻辑一致（例如某牙在某时间点被记为已拔除，却在更晚时间点又「在位/松动」且无解释）。只标记真实矛盾。
4. 时序：时间点须按非递减时间排列；t_months 合理。
5. held_out 不得泄题或过度断言（须反映原文）。

严重级别：
- "high"：真实事实错误、错误/臆造的数字，或逻辑矛盾。
- "medium"：无支撑或不精确的陈述，或时序问题。
- "low"：仅格式/措辞问题。

只返回严格、合法的 JSON：
{
  "passed": true 或 false,        // 存在任一 high 级问题即为 false
  "issues": [
    {"severity": "high|medium|low",
     "location": "时间点标签 / 主题 / held_out 字段",
     "problem": "问题所在",
     "source_evidence": "来自 (A) 的、证明正确值的简短引文，或 'NOT FOUND IN SOURCE'",
     "suggested_fix": "修正该抽取的具体指令"}
  ]
}

===== SOURCE (A)：图注 =====
$figures_block

===== 待校验的抽取时间线 (B) =====
$timeline_json

===== SOURCE (A)：时间线表格 =====
$tables_text

===== SOURCE (A)：全文 =====
$fulltext
```

# 第二步（证据抽取与关系图）

## 2.1 原子证据抽取 
逐个阶段、逐条问答，把医生说过的话提炼成一条条最小的客观临床事实。

```
你正在构建 OralMemBench —— 一个面向口腔颌面临床推理的多模态纵向记忆评测基准。

请仅从「当前阶段」的问答内容中，抽取原子级的临床事实。

规则：
1. 只抽取原始问答答案中「明确陈述」的事实。
2. 不要推断最终诊断或治疗方案。
3. 把复合句拆分成最小的原子事实。
4. 数值、单位、牙位、左右侧别、否定表述必须原样保留、不得改动。
5. fact_text 用简洁的英文书写。
6. 只返回严格的 JSON。
7. 每条原始问答最多抽取 12 条临床上重要的事实。

返回格式：
{
  "atomic_evidence": [
    {
      "source_turn_id": 5,
      "modality": ["DP"],
      "fact_text": "...",
      "fact_type": "profile|chief_complaint|history|facial_finding|occlusal_finding|cephalometric_measurement|panoramic_finding|ct_finding|tmj_finding|other",
      "clinical_dimension": "profile|sagittal_relationship|vertical_pattern|facial_asymmetry|dental_status|tmj_status|treatment_risk|other",
      "normalized": {"field": "...", "value": "...", "unit": null, "side": null, "tooth": null}
    }
  ]
}

患者：$patient_id
阶段：$stage_id
模态：$modalities

原始问答：
$qa_text
```

## 2.2 跨阶段依赖连边

把上一步提炼的事实当作节点，判断后面的检查在临床上如何依赖/印证/修正前面的检查，连成证据关系图

```
你正在构建 OralMemBench —— 一个面向口腔颌面临床推理的多模态纵向记忆评测基准。

现给你一位患者「按阶段展开的诊断检查」中抽取出的原子级临床证据节点。各阶段按临床顺序释放：stage_order 越小，表示该证据在就诊轨迹中出现得越早。每个节点包含 id、阶段、stage_order、临床维度（clinical_dimension）、归一化字段，以及一段 fact_text。

任务：提出「跨阶段」的临床依赖连边，刻画「较晚出现的证据」在临床上如何依赖、支持、细化、确认、量化、解释或更新「较早出现的证据」。要特别关注跨越「不同临床维度或不同模态」的依赖，因为这类依赖正是本基准要考察的多模态纵向推理能力。

规则：
1. 每条边都从较早的节点（source）指向较晚的节点（target）：source 的 stage_order 必须严格小于 target 的 stage_order。
2. 只有当两个节点之间存在真实、站得住脚的临床关联时才连边。绝不为了让图更大而连接无关的发现。
3. 优先连「跨维度 / 跨模态」的依赖，例如：主诉被咬合测量所支持；面部临床发现被头影或 CT 测量所确认；牙列发现被影像发现交叉印证。
4. 只能使用下方提供的节点 id。绝不可臆造 id、事实或数值。
5. relation 必须严格为以下之一：supports, refines, confirms, quantifies, explains, updates。
6. 为每条边写一句简洁的英文临床理由（一个短句，最多 15 个词）。
7. 有所取舍：最多提出 $max_edges 条高质量的边。临床有效性和质量比数量更重要。
8. 只返回严格的 JSON，不要任何解释、markdown 或 JSON 之外的推理文字。

返回格式：
{
  "edges": [
    {"source": "<node_id>", "target": "<node_id>", "relation": "supports", "reason": "..."}
  ]
}

患者：$patient_id

阶段释放顺序（由早到晚）：
$stage_order

证据节点：
$nodes
```


# 第三步（出题与评分）

## 3.1 任务规划

基于证据和关系图，规划出具体的评测任务（选哪几条证据、在第几阶段后提问、标准答案是什么）


```
你正在为一位正颌 / 颅颌面患者设计 OralMemBench 评测任务。

现给你该患者的临床阶段（按临床顺序释放）、从可见问诊轮次中抽取的全部原子证据目录，以及证据关系图。请为该患者设计恰好 $task_count 个类型为「$task_type」的任务。所有任务都必须在医学上站得住脚，且完全基于所提供的证据。

本任务类型的定义：
$type_instruction

硬性规则：
1. required_evidence_ids 只能从下方证据目录中选取（使用精确的 id）。
2. ask_after_stage 必须是阶段列表中的某个阶段 id，且所有所需证据都必须在该阶段（含）之前就已释放（依据阶段顺序）。
3. gold_answer 必须完全由所选证据支撑。绝不可臆造证据中没有的诊断、数值或发现。
4. natural_answer 是一段简洁（不超过 4 句）、临床上自然的回答。
5. 这 $task_count 个任务在临床上必须彼此不同（关注不同的发现 / 证据）。
6. 证据必须与任务所涉的模态 / 阶段一致：required_evidence_ids 要选取属于该问题所聚焦模态 / 阶段的证据，不要混入无关模态（例如不要把主诉或照片发现挂到一道问 CT 影像的任务上）。对于跨阶段的更新 / 纠错任务，只包含「被更新的更早印象」和「更新它的更晚证据」。
7. 模态可行性：只使用「真正能从引入该发现的模态」获得的发现。不要把需要专科检查才能获得的临床检查发现（如开口度、开口型、颞下颌关节弹响）归因于照片或影像模态。
8. 当临床问题存在确定答案时，gold_answer 必须给出明确结论，而非含糊其辞。
9. 只返回严格的 JSON。

返回格式：
{
  "tasks": [
    {
      "task_type": "$task_type",
      "ask_after_stage": "S#_...",
      "required_evidence_ids": ["..."],
      "gold_answer": {"natural_answer": "..."}
    }
  ]
}

患者：$patient_id

临床阶段（释放顺序）：
$stages_text

证据目录（id | 阶段 | 模态 | 事实）：
$evidence_text

证据关系图的边（source -> target | 类型 | 理由）：
$edges_text
```

## 3.2 四类任务的定义

定义普通任务的 4 种类型、各生成几道，以及每类的具体要求。

| 任务类型 (task_type) | 数量 | 考察能力 | 定义要求（中文） |
|---|---|---|---|
| `modality_perception`（模态感知） | 3 | 单次检查内可直接观察到的发现 | 读取在单个阶段 / 单个模态内可直接看到的发现；所需证据应来自同一个阶段。 |
| `longitudinal_evidence_recall`（纵向证据回忆） | 2 | 在后续阶段回忆更早的信息 | 在较晚阶段推理时，回忆起较早阶段引入的证据；**答案必须点明更早的临床来源 / 阶段**；所需证据应至少跨越两个不同阶段。 |
| `cross_modal_reasoning`（跨模态推理） | 2 | 串联多次检查得出结论 | 整合多个阶段 / 多个模态的证据，推断出骨性、不对称或功能模式；所需证据应至少跨越两个不同阶段。 |
| `memory_update_conflict_correction`（记忆更新 / 纠错） | 2 | 后续检查修正早先判断 | 解释后续阶段的证据如何确认、细化或纠正更早阶段的印象；所需证据应至少跨越两个不同阶段。并把更新范围限定在「单一模态关系」内：只包含被更新的更早印象、以及（所问模态 / 阶段的）更新它的更晚证据，使评分只针对该更新关系、而非无关发现。 |

## 3.3 生成问题

把规划好的任务转写成一句临床上自然、又不泄露答案的问题。

```
你正在协助构建 OralMemBench 评测问题。

请为给定的任务规格生成一句临床上自然的问题。该问题应能考察预期的记忆 / 推理能力，但绝不能泄露答案。

规则：
1. 写成一句英文问题。
2. 不要提及任何证据 id。
3. 不要逐字照抄原始问答里的问题。
4. 不要泄露数值或最终结论，除非该任务明确要求模型去回忆它们。
5. 对于「回忆类」任务，要同时询问「记住的内容」及其「临床来源 / 阶段」。
6. 对于「更新类」任务，要询问后续证据如何确认、细化或纠正更早的证据。
7. 把问题限定在「一个」清晰的模态 / 阶段对象上。若问题点名了某模态或阶段（如「CT 发现」），就只能问该模态 / 阶段所能提供的内容，不得在同一问题里要求另一模态 / 阶段的内容。
8. 问题中点名的任何检查 / 影像模态或阶段，必须与其所指证据的真实模态一致（见下方术语表）。绝不重命名或臆造模态——例如不要把口内牙科照片称作「全景片」或「X 光」。若不确定，就用其所属阶段来指代该发现，而不要臆造影像类型。
9. 只返回严格的 JSON。

模态术语表（证据模态代码 -> 实际检查类型）：
- FP  = 面部照片
- DP  = 口内牙科照片（这不是放射片 / 不是 X 光）
- XR  = 头影测量片与全景片（X 光）
- XLData = 头影测量数据
- CT  = 三维 CT
- TMJ = 颞下颌关节临床检查
- TEXT_QA = 患者基本信息 / 病史（文字问诊）

返回格式：
{
  "question": "...",
  "clinical_chain": "..."
}

患者：$patient_id
任务类型：$task_type
在此阶段后提问：$ask_after_stage
标准答案：$gold_answer

可用于支撑答案的证据：
$evidence_text

$feedback_block
```

## 3.4 问答校验

给已生成的问题和标准答案把关，检查是否泄题、是否可答、类型是否匹配、模态是否用对；能修则修（改问题或裁剪答案），不能修才拒。

```
你正在校验一道 OralMemBench 评测问答题。

请判断该问题与标准答案对于所要求的任务类型是否有效。

校验标准：
1. 问题不得泄露或复述答案。
2. 问题在指定阶段之后必须可回答（所需证据在此之前都已释放）。
3. 任务类型必须与所考察的能力相匹配。
4. 临床推理必须合理，且不得引入无证据支撑的诊断。
5. 标准答案必须以所列证据为依据。其核心临床主张（诊断、数值、关键发现）必须有证据支撑。
6. 模态准确性：问题中点名的任何检查 / 影像模态，必须与其所指证据的真实模态一致（见术语表）。若问题点错了模态（如把口内牙科照片称作「全景片」或「X 光」），即判为无效——返回一个使用正确模态（或以阶段指代该发现）的 "fixed_question"。

模态术语表（模态代码 -> 实际检查类型）：
- FP = 面部照片；DP = 口内牙科照片（非放射片 / X 光）；XR = 头影测量片与全景片；XLData = 头影测量数据；CT = 三维 CT；TMJ = 颞下颌关节临床检查；TEXT_QA = 患者基本信息 / 病史。

「优先修复」策略（重要——尽量修复而非拒绝）：
- 若唯一的问题是标准答案含有「所列证据未支撑」的额外细节（如无对应证据的数字、测量或发现），不要拒绝。应设 "accepted": true，并返回 "fixed_answer"：一段改写后的标准答案，只保留有证据支撑的内容，保持临床自然且简洁（<= 4 句），且仍能回答该问题。不得新增任何内容。
- 若问题泄露了答案，或点错了模态，但其余无碍，则设 "accepted": true 并返回 "fixed_question"：修正后的问题。
- 只有当无法这样修复时才设 "accepted": false：问题在该阶段不可回答、任务类型错误，或答案的「核心」无证据支撑或与证据矛盾。

只返回严格的 JSON。

返回格式：
{
  "accepted": true,
  "feedback": "...",
  "issues": [],
  "fixed_question": null,
  "fixed_answer": null
}

任务：
$task_json
```

## 3.5 标准答案的证据归因

针对留作标准答案的诊断/治疗题，回溯这个结论到底依据了前面哪几条事实。

## 4.3 基础判分：整体正确性 + 逐条证据覆盖

