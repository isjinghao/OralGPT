# OralMemBench 提示词中文版


# 第零步（Report 长程病例：时间线抽取与校验反馈）

## 0.1 时间线抽取（抽取模型）

从一篇长程病例报告的正文、时间线表格与图注中，抽出**严格忠于原文、按时间排序**的结构化时间线；可带上一轮校验模型的反馈进行自我修正。

```
你正在从一篇已发表的口腔/颌面/牙科长程病例报告，构建 OralMemBench-Longitudinal —— 一个按「时间轴」组织的多模态纵向记忆评测基准。

你的任务：阅读报告正文及其时间线表格，产出一份严格忠于事实、按时间顺序排列的结构化时间线。这必须能泛化到任意此类报告，因此请从文本中推断结构；不要假定固定的疾病或固定的就诊次数。

硬性规则：
1. 只使用 SOURCE 明确陈述的事实，原样保留数字、单位、牙位、侧别、日期、变异和否定表述；叙述与表格冲突时以表格为准。答案尽量保留完整原文，只清理明显的空格/版面伪影，不增加事实或猜改不清楚的值。
2. 完整抽取真实临床时间点。最早明确事件即使与后续首诊写在同一句，也要单独作为 t_months=0 的首个 timepoint；后续时间点按时序排列。所有后续 t_months 都表示从该最早事件起经过的非负整数月，可依据原文年龄或日期估算，进入治疗阶段也不得重置原点；不足一个月的相邻事件可使用同一整数值。原文合并报告且没有独立发现的多次访视保留为一个联合 timepoint，不复制相同答案。
3. stage_type 只使用 perception、treatment、followup，且按该顺序排列；分期治疗中的愈合、检查、二期暴露和最终操作或修复都属于 treatment，完成后才进入 followup。同一日期跨阶段时拆成连续 timepoint。
4. 每条 QA 的 role 为 observation 或 evaluation：observation 是可见记忆，evaluation 先由评测模型作答，再释放论文答案。
5. perception 只含 observation。每个与 perception 或 followup 发现关联的临床相关可用图片都生成一条综合图片 QA，覆盖正文关联的直接视觉发现，不能只复述图注；图片 QA 放在会泄露其答案的重叠文本之前，非视觉测量或解释作为文本 observation；不生成综合推理题。
6. treatment 只含 evaluation；按论文内容覆盖每个重要计划、实际操作、术式选择、中间检查和理由，不固定数量，也不附加治疗图片；同批 evaluation 互不展示答案。
7. 每个真实 followup 时间点先放 observation，再放原文支持的状态、稳定性/复发和后续管理 evaluation；同批 evaluation 互不展示答案。
8. 问题必须由对应论文答案和时间点生成，针对论文且不泄露答案。
9. 只有正文或图注明确关联图片的 observation 可设置 figure_ref；evaluation 的 figure_ref 为 null。多个 panel 对应同一提取图片时只生成一条综合图片 QA。
10. 只按给定结构返回严格合法 JSON。

输出 JSON 结构：
{
  "timepoints": [
    {
      "date_text": "原文日期/时期",
      "t_months": 距最早时间点的整数月数,
      "stage_type": "perception | treatment | followup",
      "modality": ["TEXT_QA","DP","XR","CT","DERM","GENE", ...],
      "qa_pairs": [
        {
          "role": "observation | evaluation",
          "question": "不泄露答案的论文特异问题",
          "answer": "尽可能保留的论文原文答案",
          "figure_ref": "Figure N 或 null"
        }
      ]
    }
  ]
}

可用于 figure_ref 的图（标签 -> 图注，可能为空）：
$figures_block

$feedback_block

===== SOURCE：时间线表格（逐时间点数值以此为准） =====
$tables_text

===== SOURCE：全文 =====
$fulltext
```

## 0.2 时间线校验（校验模型 / critic）

对照原文、表格与**图注**，逐条核验抽取出的时间线；输出问题清单与修正建议，回灌给抽取模型形成反馈闭环。**图注也算原文的一部分**，并**禁止自行做算术**，以避免把原文确有的事实误判为「臆造」。

```
你是一名严格的医学事实核查员，服务于一个纵向口腔/牙科病例报告基准。
给你 (A) 原始报告正文、时间线表格，以及其「图注」，和 (B) 从中抽取的结构化时间线。请「仅」依据 (A) 校验 (B)，不得使用外部知识。

什么算作 SOURCE (A)：下方的全文、时间线表格，以及图注「全都」是原文的一部分。图注中陈述的事实即为「有支撑」（不要判为臆造）。

核查项：
1. 每条答案都有原文支持，尽量保留完整原文及重要数值和否定表述，不保留明显的空格/版面伪影；冲突时以表格为准，不猜改不清楚的值。
2. 问题与答案及时间点一致，且不泄露答案。
3. 最早事件单独作为 t_months=0 的首个 timepoint；所有后续 t_months 均为从该原点经过的非负整数月，治疗阶段不得重置，不足一个月的相邻事件可共享同一整数值；后续时间点完整、按时序排列，stage_type 遵循 perception → treatment → followup，分期治疗直到最终操作或修复完成都属于 treatment。原文合并报告且没有独立发现的多次访视保留为一个联合 timepoint，不拆成重复 QA。
4. perception 只含 observation；treatment 只含 evaluation，并按论文覆盖计划、操作、选择、检查和理由且不固定数量；followup 先 observation，再放原文支持的状态和管理 evaluation。
5. 每个与 perception 或 followup 关联的临床相关可用图片都有一条综合图片 QA，覆盖正文关联的视觉发现而非只复述图注，放在会泄露答案的重叠文本之前；非视觉测量或解释放在文本 observation。
6. evaluation 的 figure_ref 必须为 null，同批 evaluation 的答案互不展示。

严重级别：
- "high"：真实事实错误、错误/臆造的数字，或逻辑矛盾。
- "medium"：无支撑或不精确的陈述，或时序问题。
- "low"：仅格式/措辞问题。

只返回严格、合法的 JSON：
{
  "passed": true 或 false,        // 存在任一 high 级问题即为 false
  "issues": [
    {"severity": "high|medium|low",
     "location": "时间点标签 / QA 主题 / 问题 / 答案 / role / stage_type",
     "problem": "问题所在",
     "source_evidence": "来自 (A) 的、证明正确值的简短引文，或 'NOT FOUND IN SOURCE'",
     "suggested_fix": "修正该抽取的具体指令"}
  ]
}

===== SOURCE (A)：图注 =====
$figures_block

===== 待校验的抽取时间线 (B) =====
$timeline_json

===== SOURCE (A)：时间线表格 =====
$tables_text

===== SOURCE (A)：全文 =====
$fulltext
```

# 第一步（报告时间轨迹与模型感知）

## 1.1 问答轮次渲染

三个阶段统一采用 `qa_pairs`，问题和答案都由论文内容驱动，`qa_render.py` 只校验与渲染，不再生成固定问题。

- `observation`：文本事实直接进入 memory；有图 QA 在标准轨迹使用论文答案，在模型感知轨迹使用视觉模型答案。无图文本在两条轨迹中完全一致。
- `evaluation`：先由模型作答，论文答案仅作 gold。治疗阶段所有问题互不共享 gold；完成整个治疗阶段后，按开关向随访释放论文治疗答案或模型治疗答案。
- followup 每个真实时间点先释放文本/图片 observation，再批量回答当前时间点的状态/复发和后续治疗问题；同一时间点内不共享答案，完成该时间点后模型答案进入下一随访时间点的 memory。
- `--release-perception-ground-truth` 默认开启；关闭后读取 `model_perception_trajectory.json`。
- `--release-treatment-ground-truth` 默认开启；关闭后向随访释放模型生成的治疗答案。
- 两个开关构成四种实验：论文感知+论文治疗、论文感知+模型治疗、模型感知+论文治疗、模型感知+模型治疗。
- 基于证据图生成的综合诊断、跨模态和纵向推理任务仍由后续 benchmark 任务生成流程负责，不与轨迹构造阶段的感知 QA 混合。

# 第二步（证据抽取与关系图）

## 2.1 原子证据抽取 
逐个阶段、逐条问答，把医生说过的话提炼成一条条最小的客观临床事实。

```
你正在构建 OralMemBench —— 一个面向口腔颌面临床推理的多模态纵向记忆评测基准。

请仅从「当前阶段」的问答内容中，抽取原子级的临床事实。

规则：
1. 只抽取当前原始问答中明确陈述的事实，不推断诊断或治疗方案。
2. 把复合句拆成最小事实，原样保留数值、单位、牙位、侧别和否定。
3. modality 必须来自当前阶段；患者病史 / 主诉使用 TEXT_QA，禁止标为 DP。
4. fact_text 使用简洁英文；每条问答最多抽取 12 条重要事实；只返回 JSON。

返回格式：
{
  "atomic_evidence": [
    {
      "source_turn_id": 5,

$qa_text

## 2.2 跨阶段依赖连边

把上一步提炼的事实当作节点，判断后面的检查在临床上如何依赖/印证/修正前面的检查，连成证据关系图

```
你正在构建 OralMemBench —— 一个面向口腔颌面临床推理的多模态纵向记忆评测基准。

现给你一位患者「按阶段展开的诊断检查」中抽取出的原子级临床证据节点。各阶段按临床顺序释放：stage_order 越小，表示该证据在就诊轨迹中出现得越早。每个节点包含 id、阶段、stage_order、临床维度（clinical_dimension）、归一化字段，以及一段 fact_text。

任务：提出「跨阶段」证据关系候选。候选仅限于较早事实可能帮助解释较晚事实的情况；不要把仅仅相似、共现或宽泛相容的事实作为候选。

规则：
1. 每个候选都从较早节点指向较晚节点。
2. 严格保持实体、解剖层级、范围、方向、极性和不确定性。
3. 只能使用给定节点 id，不得臆造 id、事实或数值。
4. 每个候选使用不超过 15 个英文词的事实特异理由。
5. 最多提出 $max_edges 个候选。

返回格式：
{
  "candidates": [
    {"source": "<node_id>", "target": "<node_id>", "reason": "..."}
  ]
}

患者：$patient_id

阶段释放顺序（由早到晚）：
$stage_order

证据节点：
$nodes
```

候选边由独立审核器分为「临床支持」「背景相容」或拒绝；背景相容边只用于可视化，不参与任务推理。

你正在独立审核跨阶段证据关系候选。

对每个候选只分类一次：

直接支持不能仅基于同类别、共现或宽泛相似。严格保持实体、解剖层级、范围、方向、极性和不确定性。

只返回严格 JSON：
{
  "clinical_support": [
    {"source": "<node_id>", "target": "<node_id>", "reason": "..."}
  ],
  "context_consistency": [
    {"source": "<node_id>", "target": "<node_id>", "reason": "..."}

候选：
$candidates

证据节点：
$nodes

每类最多接受边数：$max_edges

# 第三步（出题与评分）

## 3.1 任务规划

基于证据和关系图，规划出具体的评测任务（选哪几条证据、在第几阶段后提问、标准答案是什么）


```
你正在为一位正颌 / 颅颌面患者设计 OralMemBench 评测任务。

现给你该患者的临床阶段（按临床顺序释放）、从可见问诊轮次中抽取的全部原子证据目录，以及证据关系图。请为该患者设计恰好 $task_count 个类型为「$task_type」的任务。所有任务都必须在医学上站得住脚，且完全基于所提供的证据。

本任务类型的定义：
$type_instruction

硬性规则：
1. required_evidence_ids 只能从下方证据目录中选取（使用精确的 id）。
2. ask_after_stage 必须是阶段列表中的某个阶段 id，且所有所需证据都必须在该阶段（含）之前就已释放（依据阶段顺序）。
3. gold_answer 必须完全由所选证据支撑，简洁自然，并且不得出现 S1_FP、S4_CT 等内部阶段 ID。
4. natural_answer 是一段简洁（不超过 4 句）、临床上自然的回答。
5. 这 $task_count 个任务在临床上必须彼此不同（关注不同的发现 / 证据）。
6. required_evidence_ids 必须构成临床推理所需的充分证据集合。凡是对答案或推理链有实质作用的事实都应纳入；不得为了减少数量而删去所需的交叉印证，只排除与任务无关的事实。
7. 证据必须与任务所涉的模态 / 阶段一致：required_evidence_ids 要选取属于该问题所聚焦模态 / 阶段的证据，不要混入无关模态。对于跨阶段的更新 / 纠错任务，只包含「被更新的更早印象」和「更新它的更晚证据」。
8. 模态可行性：只使用真正能从引入该发现的模态获得的发现，不要把专门临床检查结果归因于照片或影像。
9. 保持证据原有的确定性和范围，不要把有限、近似或带限定的发现改写为绝对结论。
10. 比较或因果结论必须有支撑该关系的证据，不能仅凭相关事实同时存在。
11. 在声称较晚证据新增、细化、更新或纠正信息前，必须对照此前全部可用证据，而非只看所选子集；不得通过遗漏既有事实制造新颖性。
12. 更新或纠错的答案必须明确陈述此前不可得的较晚事实；单纯确认或测量差异不构成更新。
13. 每个所选模态都必须必要，来源表述不得命名不同的检查来源。
14. 临床问题存在确定答案时，gold_answer 应在不超出证据的前提下给出明确结论。
15. 只返回严格的 JSON。

返回格式：
{
  "tasks": [
    {
      "task_type": "$task_type",
      "ask_after_stage": "S#_...",
      "required_evidence_ids": ["..."],
      "gold_answer": {"natural_answer": "..."}
    }
  ]
}

患者：$patient_id

临床阶段（释放顺序）：
$stages_text

证据目录（id | 阶段 | 模态 | 事实）：
$evidence_text

证据关系图的边（source -> target | 类型 | 理由）：
$edges_text
```

## 3.2 四类任务的定义

定义普通任务的 4 种类型、各生成几道，以及每类的具体要求。

| 任务类型 (task_type) | 数量 | 考察能力 | 定义要求（中文） |
|---|---|---|---|
| `modality_perception`（模态感知） | 3 | 单次检查内可直接观察到的发现 | 读取在单个阶段 / 单个模态内可直接看到的发现；所需证据应来自同一个阶段。 |
| `longitudinal_evidence_recall`（纵向证据回忆） | 2 | 在后续阶段回忆更早的信息 | 在较晚阶段推理时，回忆起较早阶段引入的证据；**答案必须点明更早的临床来源 / 阶段**；所需证据应至少跨越两个不同阶段。 |
| `cross_modal_reasoning`（跨模态推理） | 2 | 串联多次检查得出结论 | 整合多个阶段 / 多个模态的证据，推断出骨性、不对称或功能模式；所需证据应至少跨越两个不同阶段。 |
| `memory_update_conflict_correction`（记忆更新 / 纠错） | 2 | 后续检查补充或修正早先判断 | 后续证据必须新增临床相关事实或解决早先印象；答案必须明确该新增事实，不能把单纯确认或测量差异视为更新；所需证据至少跨越两个不同阶段。 |

## 3.3 生成问题

把规划好的任务转写成一句临床上自然、又不泄露答案的问题。

```
你正在协助构建 OralMemBench 评测问题。

请为给定的任务规格生成一句临床上自然的问题。该问题应能考察预期的记忆 / 推理能力，但绝不能泄露答案。

规则：
1. 写成一句自然的英文问题，不提 evidence_id，不照抄原始问题，也不泄露答案。
2. 问题中禁止出现 S0、S1_FP、S2_DP、S3_XR_XLA、S4_CT、S5_TMJ 等内部阶段 ID；clinical_chain 可保留为内部元数据。
3. 仅当问题确实比较不同时间的证据时，才使用「较早」「后续」等时间表达；否则直接点明检查类型。
4. 只使用所选证据对应的真实检查或影像来源，不得扩大来源范围，也不把口内照片称为全景片或 X 光。
5. 对更新或纠错任务，问题必须明确比较早期发现与后续证据新增或改变的内容。

3. 先报告客观图像发现，再给出临床解释，并区分直接观察和推断。
4. 只报告当前图片或明确提供的临床上下文支持的事实。对于综合性问题，应覆盖问题要求的类别，不要用常见模板或无法明确看到的笼统阴性结论填补遗漏。
5. 无法可靠观察或测量时应明确说明，不要猜测；如果有依据，应保留侧别、牙位、正负号、单位和定性类别，数值使用合理近似值，不要制造虚假精确度。
6. 遵守模态边界：如果问题要求的临床检查信息没有被提供，应说明无法仅凭图片确定；不能仅凭图片推断开口度、疼痛、压痛、关节弹响等结果。
7. 使用简洁自然语言；多个发现可以使用列表。不要重复同一发现，也不要提及 prompt、隐藏参考、评估、ground truth 或这些指令。

## 阶段1感知评估（verifier）

阶段1每回答一个图片感知问题后，立即调用 verifier LLM 进行事实级评估。评估输入包括：清理后的问题、该 `source_turn_id` 对应的原子证据、标准轨迹答案和模型回答。verifier 只返回命中的 `evidence_id` 以及模型回答中的原子 claims，指标由代码计算。

实际 prompt 文件：`step1_patient_trajectory/prompts/perception_verifier.yaml`

verifier 需要判断：

- `matched_evidence_ids`：模型回答覆盖的原子证据 ID；
- `predicted_claims`：模型回答拆出的原子事实；
- 每条 claim 是否被当前 source turn 的原子证据支持；
- 是否与原子证据矛盾。

verifier 输出的核心结构为：

```json
{
  "matched_evidence_ids": ["evidence_id"],
  "predicted_claims": [
    {
      "claim": "atomic claim",
      "matched_evidence_ids": ["evidence_id"],
      "supported": true,
      "contradiction": false,
      "hallucination": false
    }
  ]
}
```

代码计算四项指标：

- `precision`：命中的模型 claims / 模型 claims 总数；
- `recall`：命中的 gold evidence / 当前题 gold evidence 总数；
- `f1`：precision 与 recall 的调和平均；
- `hallucination_control`：模型 claims 中没有被 verifier 判为编造、矛盾或不合理具体化的比例；仅未被当前精选证据覆盖但合理且不矛盾的事实，不自动算作幻觉；合理的不确定性或限制性表述也不算幻觉。

当前题的 gold evidence 通过 `introduced_stage` 和 `source_turn_id` 精确匹配，不使用其他阶段的证据。每完成一道题就写入：

`outputs/group1/CHENFANG/evaluation/perception_report.json`

报告包含每题的命中数量、四项指标、verifier 判断，以及 Chenfang 全部感知问题的总体 micro 指标。`evidence_graph.json` 不参与第一阶段事实命中主评分，主要留给后续诊断、治疗和跨阶段推理评估。
